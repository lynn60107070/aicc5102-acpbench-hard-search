% ---- 4.1 Task and baseline (2-3 sentences) ----
% - A question = NL description of the domain, current state s, goal, and action schemas;
%   the answer is one ground action.
% - Direct generation = the reproduced official setup: 2-shot prompt, greedy, one call (Sec. 3).
% - Control baselines (Faheema's methods, 1-2 sentences each): structured prompting (state, goal,
%   action, progress before answering) and best-of-N with majority vote (never the validator).
%   They test whether gains come from extra reasoning or extra candidates alone.
%
% ---- 4.2 Best-first search over LLM-predicted states (the core, ~half a page) ----
% - Tree: a node = (predicted state description, action path from the root). Root = the state in
%   the question.
% - Expanding a node uses the LLM in three roles:
%   (1) Proposer: lists k = 3 candidate actions (temperature 0.7), parsed with the benchmark's own
%       action grammar.
%   (2) Predictor: writes the resulting state for each candidate, or answers NOT APPLICABLE;
%       such candidates are pruned and never scored.
%   (3) Evaluator: reasons briefly, then outputs "Score: N" (0-10, closeness to the goal).
% - Loop: always expand the highest-scored unexpanded node with depth < d = 2; stop when no node
%   is left or the budget of B = 14 calls is used up.
% - Answer: the first action on the path to the highest-scored node.
% - Cost: each expansion costs 1 + 2k = 7 calls, so B = 14 expands the root and its most promising
%   child. Best-first order matters only because of the budget.
% - Algorithm box: 8-10 lines of pseudocode (propose -> predict/prune -> score -> pick next node).
%
% ---- 4.3 What the search cannot use (2-3 sentences; key for novelty) ----
% - No planner, simulator, applicability checker, PDDL or oracle: every state and judgment comes
%   from the LLM. The official validator only scores final answers.
% - Contrast: Thought of Search \citep{katz2024tos} and LLM+P \citep{liu2023llmp} use symbolic
%   tools; new vs ToT \citep{yao2023tot} / RAP \citep{hao2023rap}: open-ended Next Action without
%   a verifier.
%
% ---- 4.4 Evaluator variants (short list; they reappear as ablations) ----
% - steps: LLM estimates remaining actions h; rank by f = depth + h (A* with an LLM heuristic,
%   \citet{hart1968astar}).
% - vote: one comparative call per expansion picks the best child (ToT evaluator).
% - random, fixed (trust the proposer's order); plus switching off state prediction / pruning.
