\paragraph{Lynn Younes.}
\emph{Tool:} Claude (Anthropic), model Claude Opus~5.5, used through Claude Code in VS Code, with
access to the project repository and the ability to run code. (The proposal stage used Claude
Opus~4.7.)
\emph{What I asked it to do, and what it gave back:}
(i) collect the paper, code, dataset and course links and organise the project materials;
(ii) plan the division of work, the schedule and the checkpoints;
(iii) build the shared experiment code (data loading with the official prompt, an LLM client with
caching and call budgets, the scoring wrapper, the experiment runner, parallel runs and tests),
including diagnosing why the official validator crashed on Windows and fixing it;
(iv) run the reproduction and main experiments and report the results;
(v) implement the search method and its ablation switches from my design, and analyse its failures
on the validation split, which led to the scoring and pruning changes and to the evaluator variants;
(vi) review my teammates' pull requests, then fix, trim and assemble all sections into the final
paper within the page limit, and write the reproduction instructions for the code package;
(vii) draft outlines and text for the introduction, method, discussion and conclusion, the
prompts appendix and this appendix, and draft team messages;
(viii) after the progress check, analyse the remaining headroom in our runs, then implement, run
and write up the two post-hoc follow-ups in Appendix~\ref{app:followups}, each with a go/no-go
criterion fixed before its validation run.
\emph{Decisions I made:} the choice of paper and research question (proposal stage); using 8B as
the main model with 70B as a second comparison; freezing the search design; the best-of-$N$ budget
($N=14$); taking over the parallel runner; and running the few-shot ablation, each after reviewing
the evidence Claude presented.
\emph{What I changed and checked:} I chose the research question, designed the search method and
made the decisions listed above; Claude's plans, code and drafts were proposals that I reviewed,
questioned and often sent back, not final results. The work was iterative: I described what I
wanted, Claude implemented it, and we went back and forth over errors, discrepancies between runs,
and gaps in my own reasoning, where Claude pointed out a flaw in my logic and we worked out how to
fix it before going further. Claude also made mistakes, for example numbers written from memory that
did not match the run files, so every number in the paper was checked against
\texttt{results/final/} before merging, and every pull request was reviewed before it was merged. I
rewrote the drafted sections to say what I meant, and I can explain every part of the code and
paper.
